# TXT/LOG 纯文本逐行表格支持设计

日期：2026-10-27

状态：设计已获用户批准；待书面规格复核后进入实施计划

## 1. 目标与边界

simpleTable 增加 `.txt` 和 `.log` 打开、编辑及保存支持。两类文件不是 CSV，不按逗号、引号或 CSV 表头规则解释，而是作为固定一列的纯文本逐行表格：

- 每个物理行对应一个数据行，每行只有一个单元格，即 n×1。
- 第一行也是数据，列名固定显示为虚拟列名“列1”。
- 单元格编辑、行编辑、筛选、排序、撤销/重做和保存继续使用统一 BigFile 引擎。
- 文件声明只让 simpleTable 成为系统“打开方式”的候选，绝不自动修改用户的默认程序。

本期不改变 CSV 的解析、编辑、保存或关联行为，不支持其他扩展名，不新增 UTF-16 等新编码，也不提供 TXT/LOG 与 CSV 的格式转换。

## 2. 系统关联与用户选择

macOS 在现有 CSV `bundle.fileAssociations` 之外增加 TXT/LOG 的 Editor 声明，使用纯文本类型。该声明只允许 Finder 把 simpleTable 列为可用编辑器：

- 用户可以始终让 TXT 或 LOG 默认由其他程序打开。
- 用户只有主动选择 simpleTable，或在“打开方式”中手动更改默认程序后，Finder 双击才会进入 simpleTable。
- 应用安装、启动和打开文件时都不得重写 Launch Services 默认关联。

Windows 沿用现有命令行、第二实例和用户手动选择默认打开方式的机制。本功能不新增注册表写入，不抢占 TXT/LOG 默认关联。

## 3. 格式识别与记录语义

新增内部文档格式 `Csv` 与 `TextLines`。磁盘打开按扩展名进行 ASCII 大小写不敏感识别；`.csv` 使用 `Csv`，`.txt`、`.log` 使用 `TextLines`。内存新建仍使用 `Csv`，既有新建表格行为不变。

`TextLines` 的解析规则：

- 支持现有 LF 与 CRLF 行尾；CRLF 的 `\r` 不属于单元格内容。
- 逗号、双引号、制表符和反斜杠都是普通字符，不分列、不剥离引号、不合并“引号内多行”。
- 中间空行是真实数据行，值为一个空字符串；只含空格的行保留空格。
- 文件末尾用于结束最后一行的换行符不额外生成一行。例如 `a\n` 是一行，`a\n\n` 是两行，第二行为空。
- 空文件沿用现有“空文件”错误，不虚构数据行。
- 继续支持现有 UTF-8、UTF-8 BOM 和 GBK 识别；BOM 只在首行首格读取时剥离，保存时按原状态恢复。

纯文本索引不运行 CSV 引号状态机，也不跳过空行。同步首屏、后台渐进索引、全量重建、RAM 排序后备和保存后重开校验必须携带同一种格式，避免不同阶段给出不同行数或内容。

## 4. 引擎接口与读取路径

`BigFile` 持有文档格式，所有源记录解析、字段非空判断、筛选扫描、记录读取、索引和保存路径按格式分派。CSV 继续调用现有 RFC 4180 宽松方言；纯文本只解码当前物理行并返回单字段。

`BigMeta` 增加 camelCase 字段 `textLines: boolean`。`BigModel` 提供对应只读查询，前端按钮状态、页签恢复、跨窗口 adopt 和保存对话框均以引擎元数据为准，不自行猜测文档内容。

TXT/LOG 打开时由引擎强制 `headerless=true`，忽略调用方要求首行作表头的参数。对已打开的纯文本档：

- 请求开启首行非列名是既有空操作语义，不增加历史、不改变脏点。
- 请求关闭首行非列名必须明确拒绝，防止第一行变成表头。
- 所有列结构操作和列重命名均拒绝，保持固定一列；单元格与行操作不受此限制。

## 5. 编辑与换行约束

纯文本档必须始终能按同一规则重开，因此一个单元格不能含有 `\r` 或 `\n`。所有可能写入单元格内容的引擎入口都在首次修改前统一校验，包括单格编辑、批量填充/清除、插行、区域粘贴及外部导入：

- 不含换行的多行剪贴板按既有多行粘贴语义写入，每行一个格子。
- 某个目标值本身含换行时，整次操作原子拒绝，不出现半次写入，并提示改用多行粘贴。
- 非法操作不改变数据、选区所依据的行号、撤销/重做历史、脏点或保存点。

普通单元格和行编辑继续使用现有历史预算、固定点确认、排序及筛选规则，不建立第二套编辑器。

## 6. 保存与另存为

TXT/LOG 保存仍是无表头纯文本：每个逻辑行只写唯一单元格，不做 CSV 引号转义，不插入逗号，不写“列1”表头。

- 原编码和 BOM 保持不变。
- 未编辑的连续源行沿用现有原始字节透传，保留其原行尾和字节表示。
- 被编辑或新增的行使用与现有写出器一致的 CRLF 行尾；允许因此形成与 CSV 相同的混合行尾语义。
- 保存后使用 `TextLines` 重建索引并校验记录数，不能按 CSV 规则误判。
- 排序保存、历史重绑定、保存失败恢复和原子换名继续复用现有机制。

纯文本档另存为只允许 `.txt` 或 `.log`，目标扩展名改变时仍保持 `TextLines`，不会把纯文本写进 `.csv`。CSV 档另存为仍只允许 `.csv`。前端默认文件名和扩展名处理与后端格式守卫保持一致。

## 7. 打开入口与界面

文件打开对话框、窗口拖放、多路径提交、启动参数、Windows 第二实例和 macOS `RunEvent::Opened` 均接受 CSV/TXT/LOG，忽略其他扩展名。路径规范化、同路径激活、最近窗口路由和跨窗口会话迁移继续共用现有队列。

纯文本档界面固定显示“列1”和首行非列名状态：

- “首行非列名”按钮保持开启但禁用，提示纯文本档始终以第一行为数据。
- 新增、插入、删除列和列重命名入口禁用或不出现在纯文本上下文菜单中。
- 筛选、排序、行操作、页签、分屏和跨窗口拖放保持可用。

## 8. 测试与验收

### Rust 自动测试

- 顺序与并行索引在 LF、CRLF、空行、逗号、引号、中文和无末尾换行下结果一致。
- 渐进索引在多种小块边界与顺序索引一致，空行不会被吞，引号不会跨行吞记录。
- TXT 与 LOG 均为 n×1、首行是数据；CSV 原有表头及空行规则不变。
- UTF-8 BOM 与 GBK 内容正确读取、筛选和保存。
- 首行模式与列结构守卫在引擎层生效，非法多行单元格操作原子拒绝。
- 单元格/行编辑、撤销重做、排序、保存、另存为及重开往返保持内容和行数。
- 启动参数与 Opened 路径规范化接受大小写不同的 CSV/TXT/LOG，拒绝其他类型。

### Node 与真实 WebView 冒烟

- 文件关联配置包含 CSV 和独立 TXT/LOG Editor 声明，且不包含设置默认程序的步骤。
- 前端所有打开入口接受三种扩展名，界面按 `textLines` 禁用表头和列结构入口。
- 冒烟使用自建小型 UTF-8 TXT/LOG 夹具，验证逗号/引号字面量、空行、首行数据、编辑保存和重开。
- 验证多行粘贴成行、格内换行拒绝、另存为纯文本以及跨窗口 adopt 后格式状态保留。
