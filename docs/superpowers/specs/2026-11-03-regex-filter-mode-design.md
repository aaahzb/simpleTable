# 列筛选第四态“正则”设计

> 日期：2026-11-03
> 状态：交互与匹配语义已获用户批准，待书面规格复核。

## 背景

当前每列筛选框右端的按钮按三态循环：

| 模式值 | 符号 | 当前语义 |
| --- | --- | --- |
| 0 | `~` | 包含匹配，忽略大小写 |
| 1 | `=` | 整格相等，忽略大小写 |
| 2 | `≡` | 整格相等，区分大小写 |

用户需要在此基础上追加独立的第四态，直接编写正则表达式筛选特殊模式，例如“开头是 a、数字、再跟大写字母”。本需求不是替换或改变前三态。

## 目标

- 点击顺序变为 `~ → = → ≡ → .* → ~`，每列独立保存当前模式。
- 第四态在逻辑单元格文本上做正则部分搜索，默认区分大小写。
- 复用统一 Rust 大引擎的并行扫描、取消、分页、排序映射、编码和编辑覆盖层路径。
- 无效正则不得破坏已显示的成功筛选结果，也不得在键入过程中反复弹模态框。
- 前三态、多重筛选及其他文档行为保持兼容。

## 非目标

- 不增加正则替换、跨列正则、全表正则或正则持久化。
- 不改变多重筛选：它仍是勾选列之间按 OR 组合的忽略大小写包含匹配。
- 不支持环视与反向引用。使用线性时间正则引擎，避免大文件上的灾难性回溯。
- 不修改真实业务数据，不引入新的文件格式或保存语义。

## 用户交互与匹配语义

第四态符号为 `.*`，悬停文案明确“正则匹配，默认区分大小写”，并提示可使用 `(?i)`。点击按钮仍只切换当前列；该列已有条件时，沿用现有防抖链重新筛选。

正则使用 `Regex::is_match` 的部分搜索语义，而不是隐式整格相等：

- `abc` 可命中单元格任意位置的 `abc`。
- `^a\d+[A-Z]+` 命中以 `a`、至少一个数字、至少一个大写 ASCII 字母开头的单元格，例如 `a12ABC-start`。
- 默认区分大小写，因此上述表达式不会命中以 `A` 开头的单元格。
- 用户可使用正则内联标志，例如 `(?i)` 忽略大小写；`^`、`$`、字符类、量词、分组和 alternation 按 Rust `regex` 语法执行。
- 多行 CSV 单元格仍作为一个完整逻辑文本匹配，不拆成多行记录。

前三态的符号、命中规则和关键字大小写处理均不改变。

## 引擎与数据流

### 模式传递

沿用 `FilterSpec.cols` 的 `(列号, 关键字, mode)` 三元组，新增 `mode = 3`，不改变 IPC 结构。`BigModel.runFilter` 和 Rust 防守性归一化仅对模式 0、1 小写化；模式 2、3 都保留用户原始关键字。

表头控件快照、跨窗口 adopt 和清除筛选继续按数值模式传递或复位，无需新增持久化字段。

### 编译与匹配

在 `Cargo.toml` 增加直接依赖 `regex = "1"`。每次筛选请求先按条件编译一次正则，再把编译结果共享给 rayon 分块；不得逐行或逐格重新编译。

编译后的正则同时服务两条现有行来源：

1. 原始源记录：`FieldScan` 继续完成引号感知字段定位、CSV 双引号还原和 BOM/编码处理，在解码后的逻辑字段文本上执行正则。
2. 插入行与编辑覆盖层：继续以当前内存中的逻辑字符串为准，执行同一编译正则。

模式 3 与模式 2 一样需要保留未折叠大小写的字段内容。UTF-8 可借用解码文本，GBK 仅在正则参与的字段上按需解码；沿用可复用字段缓冲，不建立全表字符串投影。

`can_narrow` 已拒绝任一侧含非零模式的前缀收窄，因此正则条件会自动全量扫描。完全相同条件的短路、rayon 分块、取消代际、命中分页、排序映射和多列 AND 均沿用现有实现。

### 无效表达式与状态一致性

在取走 `stable_hits`、变更 `last_spec` 或覆盖命中集之前完成所有模式 3 的编译。任一表达式无效时：

- Rust 返回带稳定 `REGEX_INVALID:` 前缀的错误，包含有问题的列号和编译原因。
- 上一次成功的命中集、排序、内容、脏态和撤销历史保持不变；没有旧筛选时仍显示全量。
- 前端识别该前缀，去掉技术前缀后在状态栏显示“正则表达式无效”及原因，不弹模态框。其他筛选错误仍走现有错误路径。
- 用户继续输入形成有效表达式后，按正常流程重新筛选并更新状态栏。

## 性能与兼容性边界

- 正则引擎提供线性时间匹配，避免用户表达式触发指数级回溯。
- 只扫描参与条件的字段，不为正则额外建立全表列缓存。
- 保留现有分块取消机制；新一次输入可中断旧扫描，迟到结果不得覆盖新结果。
- 正则模式可能比普通包含匹配慢，这是按字段执行通用表达式的预期成本，不承诺既有普通筛选基准数值不变。
- Rust `regex` 不支持环视和反向引用；文档需明确这一边界，不伪装成 JavaScript 全语法。

## 测试设计

### Rust

- 模式 3 的部分搜索、`^...$` 锚点、默认大小写和 `(?i)`。
- 用户示例 `^a\d+[A-Z]+` 的命中与不命中样例。
- UTF-8/CJK、GBK、CSV 引号、转义双引号和多行单元格。
- 编辑覆盖层、插入行、多列 AND、多重筛选叠加和排序后命中映射。
- 无效表达式在扫描前拒绝，旧命中集与 `last_spec` 保持不变。
- 正则模式禁止前缀收窄；相同有效条件仍可短路；取消继续保留旧结果。

### Node 与真实 WebView2

- `BigModel` 对模式 3 保留关键字大小写，模式 0、1、2 的既有载荷不变。
- 真实按钮完成 `0 → 1 → 2 → 3 → 0`，符号、提示和每列独立状态正确。
- 真实窗口中通过筛选框和按钮验证用户示例、命中数、分页内容与前三态回归。
- 无效正则只显示状态栏错误、不弹模态框，旧结果保持；改为有效表达式后恢复。
- 表头重建、清除筛选、页签切换和跨窗口恢复不串模式。
