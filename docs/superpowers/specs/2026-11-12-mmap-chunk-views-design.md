# 首次 mmap 转匿名 RAM 的预建块视图设计

日期：2026-11-12
状态：书面规格和实施计划已获用户确认，按计划实施

> **2026-11-13 状态更新：** 本规格描述的“预建独立块视图”已被同日 M0 直拷规格取代，不再描述当前实现。2026-11-12 的验收数值保留为历史证据；真实界面零读盘由 `scripts/probe-ui-physical-reads.mjs` 的正常 CLI 验收证明，旧预热探针不能替代。

## 1. 背景

大文件当前以完整只读 mmap 打开并完成索引。首次进入临时排序 RAM 或持久内存模式时，引擎先预留最终连续匿名 RAM，解除完整 mmap，再通过 `PositionedRead::read_at` 从原文件分块读入最终区域。

这个实现避免了第二份完整匿名目标缓冲，并满足进程私有内存预算。但用户在本机可用内存充足、文件已经完成 mmap 和索引的情况下，仍以再次发生磁盘读取为主要问题。文件读取接口命中缓存时不一定产生物理读盘，因此实现改动和物理磁盘实测必须分别验证，不能把调用 `read_at` 直接等同于物理读盘。

此前讨论过“解除完整 mmap 后再逐块重新映射”。该方式仍然先失去全部既有源视图，不能最优先保留当前热文件页，因此不采用。

本设计取代 `2026-11-10-memory-mode-design.md` 第 5 节第 7 步中“预留成功后解除完整源映射，再分块定位读取”的首次转换路径。旧设计中的连续 RAM、取消恢复、生命周期、保存和私有峰值口径继续有效。

## 2. 目标与边界

### 2.1 首要目标

1. 对已经通过 mmap 和索引热起来的文件，转换期间始终保留尚未复制部分的独立源块视图，避免主动提前解除全部源映射。
2. 首次转换不再主动执行整份文件的 `read_at`，而是直接从源块视图复制到最终连续匿名 RAM。
3. 在本机可用内存充足的热缓存场景中，以源文件物理读取为零为实测目标；若实测不为零，继续依据磁盘证据定位，不以改用 mmap 作为完成依据。

### 2.2 保持的目标

- 最终只保留一份连续匿名 RAM，继续提供统一的 `&[u8]`。
- 保留现有索引偏移、筛选、编辑、撤销重做、排序和保存语义。
- 保留取消、失败恢复、外部文件状态检查和完整 mmap 恢复路径。
- 保留转换新增私有内存不超过 `floor(X × 1.05)` 的真实进程硬门槛。
- 每块复制完成后立即解除对应源块视图，源工作集应随进度获得释放机会，而不是到结束才统一解除。

### 2.3 非目标和限制

- 不修改通用保存、保存后的文件重载或 03 单空列保存快路径。
- 不引入 `VirtualLock`、`mlock`、气球内存或系统内存压力手段。
- 不把 macOS `MS_KILLPAGES` 作为本期必要依赖。
- 不承诺系统文件缓存立即清零，也不承诺在内存压力、外部截断或其他系统活动下绝不发生物理读盘。
- 不承诺转换开始时不存在物理重叠。已驻留文件页和正在形成的匿名 RAM 可能使工作集或系统物理驻留短时接近 `2X`。
- 不用 Windows 结果替代 macOS 真机结果。

## 3. 核心概念与不变量

完整 mmap 和块 mmap 是相互独立的虚拟内存视图。它们可以覆盖同一个文件范围，但各自拥有独立的虚拟地址和生命周期。相同文件偏移可以命中同一份系统文件缓存，不会因为存在两个视图就自动复制两份文件内容。

转换使用以下所有权关系：

```text
完整视图 M0：映射整个文件
块视图集合：A、B、C……分别映射一个文件块
最终区域 R：连续匿名 RAM，按不相交块逐步启用和写入
```

必须始终满足：

1. 完整视图 M0 不是块视图的父对象或索引表，解除 M0 不代表解除块视图。
2. 在 M0 解除之前，覆盖整个文件的全部块视图已经成功建立。
3. 任何复制都只能访问仍有效的块视图，不得访问已经解除的 M0 或已复制块的旧地址。
4. 每个块视图只被其当前复制任务取得，复制结束立即释放，不能被多个工作线程同时取得所有权。
5. 最终成功后没有剩余源块视图，文档只保留 `FinishedRam`。
6. 预留或块视图建立失败发生在 M0 解除之前，因此原文档仍保持原状。

块视图是映射关系，不是物理页锁。它们避免应用主动过早解除源映射，但操作系统仍有权在内存压力下回收干净文件页。

## 4. 模块边界

### 4.1 分块载入模块

`ram_load.rs` 保留现有文件定位读取实现，供普通文件载入和保存后的文件重载使用。新增仅供首次 mmap 转换使用的预建块视图数据源，职责为：

- 从已打开的原后备文件建立覆盖全文件的独立只读块视图。
- 处理 Windows 分配粒度和类 Unix 页大小对齐，保存视图内实际数据的起始偏移和长度。
- 向现有分块并行执行器提供与工作线程兼容的块取得接口。
- 在复制、取消、错误和析构路径释放块视图。
- 提供测试可观察的源类型和视图生命周期信息，不把测试计数当作操作系统物理内存证明。

通用文件读取接口与块视图复制接口应在类型或函数命名上明确区分，避免把用户态映射复制仍命名为文件定位读取。

### 4.2 连续匿名区域

`ram_region.rs` 的预留、逐块启用、并行写入和 `FinishedRam` 继续复用。本期不改变其地址布局、连续切片接口或 03 新增的流式保存能力。

### 4.3 文档引擎

`engine.rs` 仅调整首次 `convert_mmap_to_ram` 的源准备和调用关系。`Backing`、索引代际、编辑覆盖层、历史、文件身份和内存模式生命周期不变。

手动内存模式和临时排序共用该转换核心。已经处于 RAM 后备时仍按现有逻辑返回，不重复建立视图或复制。

## 5. 转换顺序

设文件大小为 X，默认逻辑块大小为 8 MiB，最大工作线程数为 4。

1. 刷新索引状态，拒绝仍在索引的转换，并等待既有索引线程退出。
2. 读取转换前文件状态，打开原后备文件。
3. 在完整 mmap M0 仍有效时，为文件全部范围建立独立块视图。逻辑文件覆盖量为 X；实际虚拟映射长度包含起始对齐余量。默认 8 MiB 块通常不重叠，非对齐小测试块可能映射重叠范围，但每个视图只暴露所属逻辑块。
4. 执行现有内存预检并预留最终连续区域 R。块视图建立或 R 预留任一失败，都直接清理新资源并返回，M0 保持有效。
5. 将文档后备暂时移出并解除 M0。块视图集合继续有效，文件句柄按视图创建和平台实现需要保留。
6. 使用现有不相交分块并行执行器。每个任务取得一个块视图，把视图内有效范围直接复制到 R 的对应最终位置，然后立即释放该视图。
7. 取消检查、提交失败和复制失败都先结束并等待工作线程，再清理剩余视图和半成品 R。
8. 全部块完成后再次读取文件状态。只有文件状态与转换前一致，才把 R 转为 `FinishedRam` 并安装为当前 RAM 后备。
9. 文件状态变化或状态读取失败时，放弃 R，释放全部源视图并恢复完整 mmap。
10. 只有成功安装 RAM 后才提交既有内存模式或排序状态。进度、修订号和历史继续遵守原有语义。

最后一个不足 8 MiB 的块按实际长度处理。测试使用的小块和非对齐尺寸也必须正确，不能假设测试块大小天然满足 Windows 64 KiB 分配粒度。

建立全部块视图会在 M0 解除前短暂增加虚拟地址映射和内核映射元数据，但不增加等量的私有匿名内存。64 位进程可接受该虚拟范围；映射数量由 `ceil(X / 8 MiB)` 限制，不为每个系统页单独建立视图。

## 6. 复制与视图生命周期

块视图集合在准备阶段完整建立，因此“尚未复制的源范围”仍有独立视图。与此同时，正在执行复制的视图数量受工作线程数限制：

```text
准备完成时：全部剩余块视图有效，活动复制视图为 0
复制过程中：活动复制视图不超过工作线程数，剩余视图总量随完成块数下降
成功完成后：活动复制视图和剩余块视图均为 0
```

实现必须区分“已经建立但尚未调度的视图”和“线程正在复制的活动视图”。不能再用“活动源映射最多为线程数乘块大小”描述整个集合，因为未调度块也保持映射。该上界只适用于正在复制的视图及其工作集增量。

源视图在复制前不需要再生成一份临时块缓冲。目标切片就是最终 R 的对应位置，复制来源是块视图内的只读切片。

## 7. 取消、失败和外部变化

### 7.1 准备阶段失败

块视图建立、目标预留和预检都在 M0 解除前完成。失败时释放已经建立的块视图和可能存在的目标区域，直接返回错误，不需要重建 M0。

### 7.2 复制阶段取消或失败

M0 解除后发生取消、目标提交失败、复制失败或故障注入时：

1. 停止调度新块并等待已进入的任务退出。
2. 释放任务已经取得的视图、集合中尚未调度的视图和半成品 R。
3. 复用 `restore_after_conversion` 与 `map_current_backing` 重新建立完整 mmap。
4. 恢复失败时同时报告原转换错误和恢复错误，不得宣称文档已恢复。
5. 不发送伪装的成功或最终 100%，不提交内存模式状态，不改变编辑内容和历史。

现有 `ReadAfter` 故障场景继续用于验证转换读取或复制阶段失败及恢复，错误兼容性不变。目标 `CommitAt`、预留失败和恢复映射失败也继续覆盖。

### 7.3 外部文件变化

继续使用转换前后文件状态比较和既有外部变化提示。该检查不是跨平台强制文件快照，也不扩大当前 mmap 路径对外部并发写入或截断的保证范围。

## 8. 内存口径与界面估算

### 8.1 私有内存硬门槛

首次转换仍以当前文件大小 X 计算：

```text
允许的新增私有内存峰值 = floor(X × 1.05)
```

Windows 使用 `PROCESS_MEMORY_COUNTERS_EX.PrivateUsage`，macOS 使用 `task_vm_info.internal + compressed`。文件映射不是匿名私有 RAM，但目标区域、临时私有分配和运行时新增私有占用仍必须计入真实进程测量。

### 8.2 工作集与物理驻留

预建块视图用于保留源映射并逐块释放，不等同于锁定物理页。复制期间文件页与匿名 RAM 必然存在一定时间重叠，因此：

- 不把“工作集峰值永远低于 `2X`”设为无法由当前接口证明的绝对保证。
- 记录工作集峰值和转换后的回落，检查源视图没有遗留到完成之后。
- 系统文件缓存和备用列表仍可能保留干净文件页，不将其计作应用私有内存泄漏。

排序估算中的保守 `2X` 物理重叠提示暂时保留，并更新注释，说明逐块释放只能降低后续驻留，不能消除复制开始时的文件页与匿名 RAM 重叠。该提示与 105% 私有内存硬门槛分开。

## 9. 测试设计

所有新行为按 TDD 先建立能证明旧实现不满足要求的失败测试，再实现并复跑。

### 9.1 块视图单元测试

使用独立合成临时文件，覆盖：

- 单块、多块和末尾不足一块的逐字节一致性。
- 非对齐小块、跨块边界和空输入的边界行为。
- Windows 分配粒度或类 Unix 页对齐后的视图内偏移正确。
- 首次转换数据源不进入文件 `read_at` 实现。
- 每个复制任务取得对应块的所有权，活动复制视图不超过工作线程数。
- 已复制块及时释放，成功、取消和错误展开后均无剩余块视图。
- 现有文件 `load_file`、短读、提交故障和进度行为不退化。

测试观察内部视图生命周期只能证明程序所有权和映射释放顺序，不能单独证明物理页已经回收。

### 9.2 引擎回归测试

保留并运行现有转换、取消、连续取消、提交失败、读取失败、恢复失败、外部变化、编辑历史和内存模式生命周期测试。新增或调整断言以证明：

- 完整 M0 只在全部块视图和目标预留成功后解除。
- 准备失败无需恢复且原文档保持可用。
- 复制阶段失败后恢复完整 mmap，内容与历史不变。
- 成功后为连续 RAM，筛选、编辑、撤销重做和保存仍正确。
- 临时排序和手动内存模式共用新路径，已有 RAM 不重复复制。

### 9.3 真实私有峰值矩阵

继续使用真实 `memory_peak` 子进程、内部采样和外部 5 ms 采样，至少覆盖：

- convert：workers 1 和 4，preload false 和 true。
- cancel、cancel-loop、commit-fail、read-fail。
- save，确认通用保存和 03 快路径未因首次转换改动回归。

105% 私有峰值仍是硬断言。工作集单独报告，不与私有字节混算，不通过放宽百分比掩盖回归。

### 9.4 热缓存物理读盘实测

物理读盘验证与文件 API 验证分开：

1. 使用合成基准文件完成 mmap 和索引预热，确认系统可用内存充足。
2. 在同一真实转换场景分别记录当前文件读取路径和预建块视图路径的对照数据。
3. 优先使用能够归因到物理磁盘 I/O 的 Windows 磁盘事件或等价系统级测量；记录基准噪声和转换期间增量。
4. `GetProcessIoCounters`、普通 `read_at` 次数或 ProcMon 文件访问事件可以证明文件 API 活动，但不能单独作为物理磁盘读取为零的证据。
5. 若本机不能可靠隔离物理磁盘指标，明确报告“物理读盘未验证”，不得降级为缓存 I/O 计数后宣称通过。
6. 冷缓存只用于对照，不设零物理读取要求。

基准只能使用既有授权合成文件或独立合成副本，不读取、不修改、不提交真实业务文件 `price_j8888.csv`。

## 11. 完成判定

本期完成需要同时满足：

1. 首次转换由预建独立块视图直接复制，不再主动整份 `read_at`。
2. 完整 M0 只在源块视图和目标 R 准备完成后解除，每块复制后及时释放对应视图。
3. 成功、取消、失败和外部变化路径均无源视图或半成品 RAM 遗留，现有文档语义保持。
4. 真实私有峰值矩阵继续满足 105% 硬门槛，工作集和文件缓存按各自口径报告。
5. 热缓存物理读盘按第 9.4 节实测并如实报告，未达到零或无法可靠测量时不得宣称该目标已经验证。
6. 本地 exe、canonical 双构建双冒烟及文档同步完成，macOS 验证状态单独说明。
