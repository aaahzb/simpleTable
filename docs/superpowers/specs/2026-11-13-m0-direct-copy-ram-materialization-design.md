# 原 M0 直拷与双正文 RAM 物化保存设计

日期：2026-11-13
状态：设计已逐节获得用户确认，等待用户复核书面规格；尚未实施

## 1. 背景

当前首次内存化实现先建立覆盖全文件的独立 mmap 块视图，再提前解除完整 mmap M0，从块视图复制到匿名 RAM。Windows 子进程探针曾在显式预热后报告源盘 `verified_zero`，但用户使用完整 release 界面实测仍观察到转换读盘。旧探针与真实界面在预热、进程路径和采样范围上不同，因此旧结果不能证明用户的核心目标已经达成。

本设计采用用户确认的两项简化：

1. 首次转换始终保留原 M0，直接复制到最终连续匿名 RAM，全部成功后才一次释放 M0。
2. 保存不做原地变长编辑。需要整理正文时，在另一份连续匿名 RAM 中生成最终文件正文，允许旧正文与新正文短时并存；新正文完成后释放旧正文，再从新正文顺序写硬盘。

本设计取代 `2026-11-12-mmap-chunk-views-design.md` 的首次转换路线。旧规格及其验收记录保留为历史证据，但其中预热探针结论不得继续泛化为真实界面不读盘。

## 2. 目标与边界

### 2.1 目标

- 在本机可用内存充足的真实界面路径中，避免应用主动提前解除 M0 所造成的额外源盘读取。
- 转换期间不建立独立块视图，不主动执行整份文件 `read_at`，不增加显式预热。
- 内存模式的“执行列操作”只整理 RAM 正文，不写硬盘。
- 保存时最终正文已经在 RAM 中形成，再从同一正文顺序写入临时文件并原子换名。
- 保存成功后继续使用已生成的 RAM，不读取临时文件重建 RAM。
- 将首次转换、内存物化、普通保存、另存为、排序保存、失败和取消语义统一为可测试的状态转换。

### 2.2 非目标

- 不实现单份连续 RAM 的原地范围替换、尾部移动或动态扩容。
- 不为每次单元格编辑、粘贴或增删行重新生成整份文件正文。
- 不保留 03 单空列保存的独立流式双写实现；其专用性能优化不属于本期目标。
- 不改变普通 mmap 文档的编辑和非内存保存语义。
- 不使用 `VirtualLock`、`mlock`、气球内存或系统内存压力手段。
- 不承诺 mmap 页绝对驻留，不承诺所有机器和内存压力下物理读取恒为零。
- 不把应用层顺序写盘解释为物理盘区连续，也不承诺保存返回时所有字节已经物理落盘。

## 3. 核心模型

### 3.1 后备与编辑状态

首次转换成功后，连续匿名 RAM 是当前原始文件正文的后备。普通单元格编辑、粘贴和增删行继续使用现有私有覆盖层、段表、Schema 和历史结构；这些状态属于当前逻辑文档，但不要求每次小编辑都重编码整份正文。

需要形成最终文件正文时，统一执行“内存物化”：

```text
旧正文 R0 + 当前私有编辑状态
          │
          │ 同一套序列化逻辑执行两遍
          ▼
新正文 R1（完整、连续、匿名、只读完成态）
          │
          │ 新正文提交成功后一次释放 R0
          ▼
当前唯一正文 R1
          │
          │ 仅保存需要时执行
          ▼
同目录临时文件 → 原子换名
```

`FinishedRam` 继续保持只读和定长，不增加可变文件接口。

### 3.2 两段提交

保存不再被视为一个必须整体恢复旧 RAM 的事务，而是两个独立提交：

1. **RAM 提交**：新正文及所有配套状态准备完成后，原子接管当前文档；此后旧正文不再需要恢复。
2. **磁盘提交**：从当前 RAM 顺序写临时文件并换名；成功后才更新磁盘保存点和另存为路径。

RAM 提交不表示已经保存。只要当前正文与最后成功写盘内容不同，文档就保持或设置未保存状态。

## 4. 首次 M0 直拷转换

### 4.1 转换顺序

设当前文件长度为 X：

1. 刷新索引状态，拒绝后台索引尚未完成的转换，并等待既有索引线程退出。
2. 读取转换前文件长度和修改时间。
3. 保持完整 M0 为当前后备，不建立独立 A/B/C 块视图。
4. 按 X 准确预留最终连续匿名 RAM。
5. 工作线程直接从 M0 的不相交范围复制到目标 RAM 的对应位置，不经过额外完整文件缓冲。
6. 每块复制后先检查取消，再发布进度；取消先生效时不得发送伪造的最终 100%。
7. 全部工作线程退出后，再次检查文件状态，并完成目标长度和完成态检查。
8. 只有全部检查成功才安装新 RAM，随后一次释放 M0。
9. 内存模式或排序状态在 RAM 接管后提交，编辑内容、修订和历史按既有转换语义保留。

默认工作线程和块大小沿用现有有界并行复制配置。复制来源是 M0 的只读字节范围，目标是最终 RAM 的不相交可写块。

### 4.2 取消与失败

预留、复制、目标提交、取消和外部文件变化都发生在 RAM 接管之前：

- 停止调度新块，并等待已经取得任务的工作线程退出。
- 释放半成品 RAM。
- 原 M0 从未提前解除，因此直接保留原后备，不重新映射，不运行旧恢复流程。
- 不提交内存模式状态，不改变编辑内容和历史，不伪造成功进度。
- RAM 已完成最终提交后，不再因为同一取消标志回滚。

外部文件状态检查沿用现有限制。它不是跨平台强制文件快照，也不扩大外部并发写入或截断情况下的安全保证；检测到变化时走现有提示，不自动重载或丢弃修改。

### 4.3 驻留保证边界

保留 M0 只保证应用不在复制前主动解除原映射。mmap 不锁页，操作系统仍可在内存压力下回收干净文件页，因此本设计不能把“保留 M0”表述为绝对物理零读取保证。

## 5. 内存物化

### 5.1 触发时机

以下操作在持久内存模式中触发物化：

- **执行列操作**：生成新 RAM 正文并提交，不写硬盘，保持未保存状态。
- **保存或另存为**：若当前 RAM 尚未包含全部逻辑修改，先物化，再写盘。

普通单元格编辑、粘贴和增删行只更新现有私有编辑状态，不立即物化。

如果当前 RAM 已表示全部逻辑修改，且输出编码和行序没有变化，保存直接写当前 RAM，不再生成另一份正文。执行列操作后立即保存属于这种情况；列操作后又有新编辑时，保存需要重新物化。

### 5.2 两遍生成

物化必须复用同一套文档序列化逻辑，禁止分别维护“估算长度”和“实际编码”两套规则。

1. 在文档编辑锁和既有索引、保存闸门下固定本次输出结构、编码、表头和行序。
2. 第一遍把完整输出交给计数写出器，得到准确文件字节数以及索引所需的物理行和记录容量。
3. 在旧正文仍完整可用时，完成历史转换、撤销预算、固定点准备和索引容量预留。
4. 按第一遍得到的准确长度预留新 RAM。
5. 第二遍使用相同序列化入口，把完整输出直接写入新 RAM。
6. 核对实际字节数、记录数和输出结构，完成只读 RAM 完成态。
7. 任一步失败都丢弃半成品，新 RAM 不接管，旧正文和逻辑编辑现场保持可用。

两遍生成会增加 CPU 和内存扫描成本，但避免依赖 `Vec` 自动扩容。自动重新分配可能同时保留旧分配、新分配及额外容量，不符合本设计的可预测峰值口径。

### 5.3 索引、筛选与历史

- 旧索引在生成新正文期间继续提供原记录定位。
- 新索引所需容量必须在第二份正文预留前准备，避免双正文期间再发生整份索引重新分配。
- RAM 提交后复用旧索引容量扫描新正文；提交段不再执行可能失败的完整索引分配。
- 旧筛选缓存和显示偏移不得直接套用到新正文。筛选缓存随 RAM 提交失效，按现有筛选条件和新索引重新求值。
- 覆盖层和段表按现有保存提交规则归一化到新正文。
- 撤销重做沿用现有保存后的历史转换、重绑定、预算淘汰和固定点确认规则，不另设一套历史语义。
- 无法安全保留历史时，必须在 RAM 提交前请求固定点确认；用户取消则不改变旧 RAM 和编辑现场。

## 6. RAM 提交与磁盘提交

### 6.1 RAM 提交

RAM 提交前必须完成所有可失败的正文生成、历史准备和索引容量准备。

提交时只执行已准备好的状态移动：

- 安装新正文，并一次释放旧正文。
- 复用旧索引的已准备容量，扫描新正文并安装新索引。
- 清理已被正文包含的覆盖层和段表状态。
- 提交已准备的历史、Schema 和行序状态。
- 使旧筛选缓存失效。
- 保留未保存语义，不更新磁盘保存点。

RAM 提交后不允许因为后续磁盘错误恢复旧正文。旧正文已经按用户确认的顺序释放，新正文就是唯一权威后备。

### 6.2 磁盘提交

需要写盘时：

1. 在目标同目录创建临时文件。
2. 使用有界缓冲从当前 RAM 顺序写入，不重新序列化另一份完整正文。
3. 刷新并关闭写器，按现有重试和错误规则原子换名。
4. 换名成功后更新目标文件状态、保存点和未保存标记。
5. 另存为只有在换名成功后才切换会话路径。
6. 不调用 `prepare_memory_reopen`，不映射或读取临时文件来重建 RAM。

若正文自上次物化后没有变化，失败后的重试直接从同一 RAM 重新写盘，不重复生成正文。

### 6.3 失败状态

| 失败位置 | 必须保持的状态 |
|---|---|
| 第一遍计数、历史准备或索引容量准备 | 旧正文和编辑现场不变 |
| 新 RAM 预留或第二遍生成 | 丢弃半成品，旧正文和编辑现场不变 |
| RAM 提交前用户取消固定点 | 不执行物化，旧正文和编辑现场不变 |
| 临时文件创建、写入、刷新或关闭 | 保留新 RAM 和未保存状态，不恢复旧 RAM |
| 原子换名最终失败 | 保留新 RAM，原目标文件不动，另存为不切路径 |
| 外部变化导致取消写盘 | 保留新 RAM，不自动重载，不丢弃修改 |

临时文件的保留和清理沿用现有保存错误规则。最终换名失败时，不得把临时文件丢失或目标占用错误伪装成保存成功。

## 7. 操作语义

### 7.1 执行列操作

持久内存模式中，执行列操作使用当前待执行 Schema 生成最终正文：

- 物化成功才提交本次列操作及新 RAM。
- 物化失败保持执行前的文档和列操作现场。
- 不创建或写入目标临时文件，目标文件内容和修改时间不因该操作改变。
- 成功后文档保持未保存，后续小编辑继续在新 RAM 上形成私有覆盖状态。
- 非内存模式维持现有仅提交 Schema 的行为。

### 7.2 普通保存与另存为

- 普通保存只在目标换名成功后清除未保存状态。
- 另存为只在目标换名成功后切换路径和文件身份。
- 输出编码与当前 RAM 编码不一致时必须重新物化，不得直接写旧编码正文。
- 写盘失败后，新 RAM 和当前逻辑内容保留，用户可直接重试或按现有错误提示处理临时文件。

### 7.3 排序保存

排序保存沿用当前固定点确认：存在历史且尚未批准时，先请求按当前排序物化行序的确认。

批准后按当前显示顺序生成新 RAM。RAM 提交后，新正文行序为恒等顺序，已确认的固定点在内存中生效。若随后写盘失败：

- 保留已经排序的新 RAM 和固定点结果。
- 文档保持未保存。
- 不恢复排序前旧正文，不撤销已确认的内存行序物化。

执行列操作在排序模式下仍沿用现有限制。

### 7.4 外部文件变化

转换和写盘继续使用现有文件状态检查与提示。新模型不自动重载外部文件，也不因为外部变化丢弃当前 RAM 或编辑内容。

## 8. 模块边界与旧实现收敛

### 8.1 分块载入

`ram_load` 增加原 M0 只读字节范围的直接复制来源。首次转换不再使用 `MappedChunks` 或独立块视图。普通文件载入及仍需从文件重建后备的既有路径可以继续使用文件读取来源。

### 8.2 连续 RAM 区域

`ram_region` 保留地址预留、逐块启用、并行初始写入、顺序追加和只读完成态。本期不增加完成态可变切片、范围替换或扩容接口。

03 使用的旧正文渐进读取和释放机制仅由该快路径及其测试使用，随通用物化迁移一并删除，避免保留误导性的第二套保存模型。

### 8.3 文档引擎

引擎负责转换闸门、物化计划、历史与固定点、两段提交和文件身份。序列化逻辑应由普通保存与内存物化共用，普通 mmap 保存不因共用代码改变输出字节。

### 8.4 03 单空列快路径

现有未提交的 03 快路径合并到通用物化路径，不原样保留“边生成新 RAM、边写临时文件、边释放旧 RAM”的顺序。

其覆盖的以下行为测试必须迁移并继续通过：

- 规则 CSV 单个空列插入。
- 原字段、引号风格和多行内容。
- BOM、CRLF/LF 和末行无换行。
- 输出长度、记录数、索引与磁盘正文一致性。
- 生成、写盘和换名失败后的状态语义。

本期不保留该场景的专用性能优化。若基准显示通用路径存在明显性能退化，只报告测量结果，不在实施中擅自恢复第二套专用路径。

## 9. 界面与进度

- 首次转换继续使用现有非模态进度和取消入口。
- 保存与物化进度区分“计算正文、内存整理、写入磁盘”等阶段，不用同一进度事件混淆 RAM 与磁盘完成。
- 新正文完成事件必须早于旧正文释放事件，旧正文释放事件必须早于实际磁盘写入开始事件。
- 执行列操作的内存整理完成不显示为文件已保存。
- 只有目标换名成功才显示保存完成和最终 100%。
- 取消转换或固定点确认不得伪造成功，不得清除现有修改。
- 前端变更必须重新编译嵌入前端的 release exe，再运行真实界面冒烟。

## 10. 内存口径与性能报告

### 10.1 私有内存硬门槛

首次转换以当前文件字节数 X 计算：

```text
允许新增私有内存 = floor(X × 1.05)
实际新增私有内存 = 操作期间最高 PrivateUsage − 操作前 PrivateUsage
```

物化和保存以新旧正文较大字节数 X 计算同一增量门槛。旧正文在操作前已经包含于基线，因此双正文保存的新增私有正文仍约为一份新正文大小。

Windows 使用 `PROCESS_MEMORY_COUNTERS_EX.PrivateUsage`。macOS 沿用现有真实进程采样口径，Windows 结果不得替代 macOS 真机验证。

### 10.2 绝对峰值与工作集

- 首次转换的 M0 是文件映射，不计入上述匿名私有正文增量；工作集可能因 M0 驻留页与新 RAM 重叠而接近 2X。
- 双正文物化期间，正文绝对占用约为旧正文加新正文，最高约 2X；新正文提交并释放旧正文后回落到一份正文。
- 索引、覆盖层、历史、运行时和采样器开销单独报告。正文约 2X 不表示整个进程绝对内存恰好只有 2X。
- 系统文件缓存和备用列表不计作应用私有匿名 RAM 泄漏。
- 不通过把绝对峰值与增量混用来放宽或伪造 105% 门槛。

### 10.3 性能分解

转换、正文计数、RAM 生成、索引整理和磁盘写入分别计时。03 合并后记录单空列场景的通用物化耗时，不用总保存耗时掩盖内存整理成本。

## 11. 测试设计

所有新行为在实施阶段按 TDD 先建立能够证明旧实现不满足要求的失败测试，再实现并复跑。

### 11.1 首次转换

- M0 在目标预留和全部复制期间保持有效，成功后才释放。
- 首次转换不进入独立块视图或整份文件 `read_at` 路径。
- 单块、多块、尾块和并行复制逐字节一致。
- 取消、连续取消、目标提交失败、复制故障和外部变化均保留 M0，不进入重映射恢复。
- 最后一块期间取消不发送伪造 100%，最终提交后不因同一标志回滚。
- 已有 RAM 不重复转换，筛选、编辑、撤销和排序语义不退化。

### 11.2 两遍物化

- 计数长度与实际 RAM 长度完全一致，第二遍不得超出预留。
- 覆盖 UTF-8、GBK、BOM、引号、多行字段、CRLF/LF、末行无换行和纯文本逐行格式。
- 覆盖普通单元格、批量粘贴、插入行、删除行、列结构变化和不同输出编码。
- 第一遍或第二遍故障、预留故障和提交故障均不破坏旧正文及历史。
- 新 RAM 提交后索引、筛选、行数和单元格内容与新正文一致。

### 11.3 两段保存

- 新正文完成后才释放旧正文，释放后才启动磁盘写入。
- 保存成功时磁盘字节与 RAM 正文一致，保存前后使用同一新 RAM，不读取临时文件重建。
- 写盘、刷新和换名失败后保留新 RAM、未保存状态及正确路径。
- 另存为成功才切路径，失败不切路径。
- 未变化正文的重试直接写 RAM，不再次预留完整新正文。
- 执行列操作只改变 RAM，不写目标文件，并保持未保存。
