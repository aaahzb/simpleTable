# 大文件内存模式设计

日期：2026-11-10
状态：设计已获用户逐节确认，等待书面规格复核

## 1. 背景与目标

simpleTable 当前通过只读 mmap、行索引、编辑覆盖层和共享 Schema 浏览及编辑大文件。排序时可以临时把文件复制到 `Vec<u8>`，退出排序或保存后通常回到 mmap。现有临时载入是一份目标缓冲加 8 MiB 分块复制，但仍是单线程，并且在 Windows 上可能提前形成整个文件大小的 commit。

本设计新增用户主动开启的“内存模式”，目标是：

- 把大文件后备从只读 mmap 转为私有匿名内存。
- 转换过程使用有界多核分块读取，不创建第二份完整目标缓冲。
- Windows 不在复制前提交整个目标，而是先预留连续地址，再随读取逐块提交。
- 转换期间暂时解除完整源映射，降低源文件页与目标页同时驻留的程度。
- 支持取消、失败恢复、保存后继续保持、退出排序后继续保持，以及用户明确退出。
- 内存模式撤销预算按文件大小动态提高，但只设置历史上限，不预分配。
- 用真实进程内存测量证明转换峰值没有超过内部百分比，而不是只验证内部计数。

第一阶段不改变插入列、删除列、执行列操作或 Ctrl+Z 的现有语义。更极端的驻留表列操作撤销模型留到后续独立设计。

## 2. 术语与内存口径

必须区分以下指标：

| 指标 | 含义 |
| --- | --- |
| 虚拟地址空间 | 映射或预留的地址范围，不等于物理内存占用 |
| commit | 系统为私有内存提供的 RAM 与页面文件支持承诺 |
| 私有字节 | 进程私有、不能由其他进程直接共享的已提交内存 |
| 工作集 | 当前计入进程工作集的物理页，可能包含文件映射页 |
| 系统可用内存 | 受文件缓存回收和其他进程影响的系统级指标 |

“内存模式”表示脱离文件映射的私有匿名内存后备，不表示强制锁定物理页。第一阶段不调用 `VirtualLock` 或 `mlock`，操作系统在极端内存压力下仍可换页。

转换预算针对本进程可归属的转换私有内存：

```text
X = 当前后备文件总字节数

转换私有内存峰值 =
    已提交的最终文件目标页
    + 本次转换额外拥有的私有临时缓冲

要求：
转换私有内存峰值 <= floor(X × 1.05)
```

页对齐和实际临时分配都计入 5% 余量。既有行索引、编辑覆盖层、其他文档和运行时原有内存不计入本次转换新增分配。系统总可用内存不是应用可独立保证的指标。

显式入口只出现在现有大文件模式页签。目前大文件阈值为 50 MiB，高于一个内存页对 5% 余量造成的最小尺寸限制。小文件和新建文档继续沿用现有 RAM 行为，不进入这套大文件转换验收路径。

保存会替换后备文件。保存流程的峰值验收以保存前、保存后文件大小的较大者为 X；初次显式转换仍以当前后备文件大小为 X，不能借用保存口径放宽。

## 3. 状态模型

引擎增加独立的 `memory_mode` 状态，与 `ram_backed` 分离：

| 状态 | `ram_backed` | `memory_mode` | 生命周期 |
| --- | --- | --- | --- |
| 普通 mmap 文档 | 否 | 否 | 常规文件映射 |
| 临时排序 RAM | 是 | 否 | 退出排序时可释放，保存后可回 mmap |
| 新建文档 RAM | 是 | 否 | 保持现有新建文档行为 |
| 用户内存模式 | 是 | 是 | 保存和退出排序后仍保持，明确退出才回 mmap |

`memory_mode=true` 必须以存在可靠磁盘后备为前提。新建且从未保存的文档不能单独开启。临时排序 RAM 已经有完整私有缓冲时，开启内存模式只改变生命周期和预算，不再次复制文件。

元数据增加内存模式及有效撤销预算所需字段。`ram_backed` 保留给现有排序和新建文档逻辑，不能再用它推断持久内存模式。

## 4. 模块边界

### 4.1 连续私有内存区域模块

新增独立模块，封装平台相关实现和全部必要 unsafe 代码。其职责仅限：

- 为指定长度预留连续地址空间。
- 按不相交范围提交或启用目标页面。
- 提供供并行读取写入的有界目标区间。
- 完成后提供连续只读字节视图。
- 在成功、取消、错误和析构路径释放全部资源。

Windows 使用“预留后逐块提交”。仅预留不提交整个 X。macOS 使用匿名映射，按块写入触发按需分配。其他引擎代码只接触安全接口，不直接操作平台指针。

### 4.2 分块载入模块

新增独立模块负责：

- 文件元数据和可用内存预检。
- 有界并行定位读取。
- 取消与进度。
- 转换私有内存记账。
- 半成品清理。

显式内存模式和临时排序载入复用同一转换核心。是否设置 `memory_mode` 由引擎调用方决定。

### 4.3 文档引擎

引擎继续负责后备、索引、Segment、覆盖层、Schema、历史、保存点和文件身份。转换成功前不提交新文档状态。恢复时使用后备身份 `backing_path`，不能误用用户保存路径替换固定点 generation 的后备。

## 5. 转换执行流程

1. 前端提交格内编辑和编辑窗格写回。
2. 确认当前是大文件页签、索引已完成，且没有保存、排序载入或结构生成任务。
3. 检查后备文件可读并记录大小、修改时间及现有外部变更状态。已有外部变更时拒绝转换，先走现有重载提示。
4. 显示文件大小、转换私有内存上限、当前可用物理内存；Windows 同时检查可用 commit。
5. 用户确认后，在后台阻塞任务中执行，当前文档持写锁，其他页签和窗口保持可用。
6. 预留 X 的连续地址空间。预留失败时原 mmap 完全不动。
7. 预留成功后解除完整源映射，从原后备文件分块定位读取。
8. 多核分别读取不相交目标区间，数据直接写入最终缓冲，不经过第二份完整目标或每线程文件暂存。
9. 按已完成字节累计进度。只有成功才发送最终 100%。
10. 核对读取字节数和文件状态，保留现有索引及 `index_epoch`，完成后一次性切换后备、`memory_mode` 和有效撤销预算。

初始内部参数：

```text
转换临时余量比例 = 5%
读取块大小 = 8 MiB
最大并行读取任务数 = 4
实际并行度 = min(可用并行度, 4)
```

这些参数是内部调优项，不增加用户设置。直接读入最终目标意味着在途块本身就是最终 X 的一部分，不能再把每个在途块额外计算成一份复制缓冲。

## 6. 取消、失败与外部变化

### 6.1 取消

- 取消命令只设置原子标志，不等待文档写锁。
- 停止调度新块，等待有限数量的在途读取退出。
- 释放半成品连续区域，再重新映射原后备文件。
- 恢复完成后才向前端返回取消结果。
- 不修改文件、修订号、编辑内容、选区所对应的数据或撤销历史。
- 取消和失败不发送伪装的最终 100%。

### 6.2 失败

预留、提交、读取和完成校验失败都走统一清理与恢复路径。只要原后备文件仍可读取，就恢复原 mmap 读路径和文档状态。若恢复映射也失败，错误必须同时包含转换失败与恢复失败，不能宣称文档已恢复。

资源所有权由区域守卫管理，确保提前返回和错误展开不会遗留整份已提交目标。

### 6.3 外部文件变化

转换前后检查文件大小和修改时间。转换期间检测到变化时：

- 放弃新缓冲并恢复 mmap。
- 立即进入现有外部文件变更提示。
- 转换器不自动重载，不主动丢弃未保存修改。
- 用户确认重载前，当前编辑状态仍由原会话保留。

本功能不扩大现有外部写入竞争的保证范围，也不能把大小和修改时间检查描述成跨平台强制文件快照。

## 7. 界面与生命周期

### 7.1 工具栏和状态栏

- 大文件工具栏新增“转为内存模式…”。
- 索引中、转换中或其他互斥任务中禁用。
- 开启后按钮变为“退出内存模式”，状态栏显示“内存模式”。
- 已经是临时排序 RAM 时，开启只更新状态，不显示第二次复制进度。
- 退出后恢复 mmap，并保留未保存编辑和撤销历史。
- 排序状态、临时 RAM 状态和持久内存模式状态分别显示，不再混成一条“已排序内存”提示。

### 7.2 排序兼容

- 内存模式下排序不再请求第二次文件载入。
- 退出排序时，即使前端原本请求释放排序 RAM，引擎也保留 `memory_mode` 的后备。
- 只有明确点击“退出内存模式”才释放持久后备。
- 保存排序结果后仍保持内存模式。
- 退出排序的状态提示不得再统一宣称已经释放排序内存。

### 7.3 保存与另存为

保存继续使用“写临时文件、完整校验、原子替换”流程：

1. 使用当前 RAM 写出并校验临时文件。
2. 完成所有仍依赖旧 RAM 的历史转换、索引和准备工作。
3. 释放旧 RAM。原后备文件仍可用于失败恢复。
4. 用同一分块转换核心把校验后的临时文件读入新 RAM。
5. 原子换名成功后提交新后备、新索引、新保存身份和转换后的历史。
6. 分配、读取或换名失败时，丢弃半成品并重新映射旧后备，保留原编辑和历史。

该顺序避免同时持有旧 X 和新 Y 两份完整匿名缓冲。保存后的文件大小变化会触发有效撤销预算重新计算。无路径新建文档不进入此恢复策略，因为它没有可靠磁盘副本，继续保持现有保存语义。

## 8. 撤销内存设置

“撤销内存…”对话框保留普通预算，并增加“内存模式撤销预算”。

已确认的参数：

```text
普通预算：沿用现有 1–1024 MiB，默认 64 MiB
驻留撤销百分比：默认 100%
允许范围：0%–1000%
输入步长：0.1%
内部存储：整数千分比，100% = 1000‰
```

设置页直接显示：

```text
普通文档有效预算 = 普通预算

内存模式文档有效预算 =
    max（普通预算，当前后备文件总字节数 × 驻留撤销百分比）
```

设置页还显示当前文档实时试算：普通预算、当前文件大小、输入比例、当前有效预算，以及若开启内存模式后的有效预算。0% 表示内存模式仍只使用普通预算。

预算只在以下情况套用驻留比例：

- 用户明确开启 `memory_mode`。
- 文档仍处于该模式并发生文件大小或全局设置变化。

临时排序 RAM 和新建文档不自动套用驻留比例。

更新规则：

- 开启后按当前文件大小提高有效预算。
- 退出后恢复普通预算。
- 普通预算和驻留百分比通过一个命令原子更新所有文档及未来文档，避免中间状态。
- 保存后按新后备文件大小重新计算。
- 使用向上取整和检查溢出的整数运算，不用浮点比例直接计算字节。
- 提高预算不预分配内存；历史仍只按实际共享分配计费。

缩容沿用现有最旧历史淘汰和固定点机制：

- 全局设置调低可能淘汰历史，设置页明确提示。
- 退出内存模式若会因恢复普通预算而淘汰历史或建立固定点，先显示确认；取消则不退出。
- 保存后文件变小导致的自动缩容不额外弹窗，但同步最新元数据、脏点和撤销按钮。

转换 5% 与驻留撤销百分比完全独立。前者是内部转换余量，后者是用户历史上限。

## 9. 测试设计

### 9.1 Rust 功能与恢复测试

按测试驱动开发逐条建立失败用例，再实现功能：

- 转换前后原始字节、行列内容、筛选结果和未保存编辑一致。
- UTF-8、GBK、带引号换行、末行无换行及纯文本逐行模式。
- 插入行、删除行、共享 Schema 列历史及撤销重做。
- 在预留、分块提交、读取、完成校验和恢复映射阶段分别注入失败。
- 在不同进度点取消，验证资源释放、恢复、单调进度、修订号和历史不变。
- 临时排序 RAM 开启内存模式不再复制。
- 保存、另存为、排序保存和退出排序后仍保持内存模式。
- 保存文件变大或变小，不同时保留旧、新两份完整匿名缓冲。
- 保存换名失败及保存中的分配失败可恢复旧编辑和历史。
- 退出内存模式回 mmap；缩容确认取消时不退出。
- 预算默认值、0%、0.1% 步长、整数舍入、溢出、全局原子更新和保存后重算。

### 9.2 真实内存区域测试

Windows 使用真实区域实现查询实际提交状态：

- 预留完成后不能已经提交整个 X。
- 分块提交量只能单调增加。
- 最终提交量包含页对齐后仍须在预算内。
- 取消和失败释放整个区域。
- 进程私有字节与工作集分别记录。

macOS 使用匿名私有内存计数和映射区域审计建立等价测试。不能用 Windows 的结果代替 macOS 实际验证。

### 9.3 105% 真实峰值硬验收

真实峰值测试是发布阻断项，不能只运行内部记账测试，也不能因测量波动直接放宽百分比。

测试使用独立子进程和真实转换实现，不用模拟分配器代替验收：

1. 子进程完成预热后，记录转换前进程私有字节基线。
2. 启动真实文件转换。
3. 在每次预留、分块提交和临时分配前后读取实际进程内存。
4. 外部监测进程同时以 5 ms 间隔采样，降低仅依赖转换器自身计数或漏掉瞬时峰值的风险。
5. 对每次实测峰值执行硬断言：

```text
允许峰值增量 = floor(X × 1.05)
实际峰值增量 = 转换期间进程私有字节峰值 - 转换前私有字节基线

必须满足：实际峰值增量 <= 允许峰值增量
```

初次显式转换的 X 是当前后备文件大小。保存路径单独测量，X 取保存前后文件大小的较大者。任一实测超出即失败，必须调查和修正，不能直接改成 106% 或 110%。

覆盖矩阵：

- 本地 release 验收至少使用 64 MiB、256 MiB、1024 MiB 的生成夹具。
- 64 MiB 夹具覆盖并行度 1、2、4，以及源映射未预读、已预读两种状态。
- 覆盖正常完成、中途取消、失败恢复及保存后重新建立内存后备。
- 重复执行取消和恢复，检查没有逐次残留一份已提交目标。
- CI 使用适合 runner 资源的较小真实夹具执行同类硬断言。
- debug 用于功能和诊断，release 实测是最终验收必要证据。

每次验收报告列出：文件大小 X、允许峰值、基线、实测私有字节峰值、实际增量、剩余余量或超出量、通过或失败。工作集、文件缓存和系统可用内存另行记录，但不能替代私有内存硬断言，也不能把内部计算通过当成实测通过。

### 9.4 前端与真实 WebView2

Node 测试覆盖：

- 设置页公式、实时试算、输入校验和持久化。
- 按钮状态、进度、取消、失败和外部变化提示。
- 临时 RAM 转持久模式不调用第二次载入。
- 内存模式下退出排序不显示已释放内存。
- 退出导致历史缩容时的确认与取消。

真实 WebView2 使用测试生成文件完成开启、取消、编辑、撤销、保存、退出排序和退出内存模式。前端变化后重新构建内嵌前端的 debug、release exe，分别运行完整 smoke。

完整运行现有 Node、Rust 和双 WebView2 回归。macOS 由 `macos-15` CI 覆盖编译及可自动运行的测试，真实 WKWebView 交互单独实机验证。

默认测试不生成 20 GiB 文件。后续大文件基准只能只读使用 `E:\simpletable_hdd_test\bench_22gb.csv`，不得修改基准原文件，不读取或试验真实业务文件。

## 10. 文档与完成标准

README、使用指南和项目进度文档同步说明：

- 内存模式与临时排序内存的区别。
- 转换 5% 的计量边界及真实峰值验收结果。
- 不强制锁定物理页。
- 保存、另存为和退出排序后的生命周期。
- 设置页公式、实时试算和缩容影响。
- 第一阶段不改变列操作和 Ctrl+Z 语义。

完成必须同时具备：

- 功能、取消、失败恢复和生命周期测试通过。
- 真实进程私有内存峰值硬验收通过，并保留实际数值报告。
- 全量 Node、Rust、debug/release WebView2 回归通过。
- 新构建的 debug、release exe 时间戳和 smoke 结果对应本次改动。
- 文档与最终行为一致。

## 11. 明确排除项

- 不实现新的驻留表列操作交互或极端 Ctrl+Z 语义。
- 不把共享 Schema 列操作改成全表物理重写。
- 不强制锁定全部物理页。
- 不承诺整个操作系统可用内存在任何瞬时只下降固定百分比。
- 不使用真实业务 CSV 做开发、故障注入或基准。
- 不因内存模式改变现有保存原子性、编码、外部变更确认和固定点协议。
